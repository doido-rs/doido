This tutorial builds a small but complete blog on top of the [Getting
started](@/docs/tutorials/getting-started.md) foundation. By the end you'll have:

- a **public** front page that lists published posts and a page for reading one,
- **comments** that any reader can leave on a post,
- an **author admin area** — a `/admin` section, protected by
  [`doido-auth`](@/docs/reference/auth.md), where the author writes and publishes posts.

It's a plain HTML app (no API), and every step uses the most basic implementation that
works, so you can see the moving parts clearly.

Here is the route map we're heading toward:

| Method | Path | Who | Purpose |
|--------|------|-----|---------|
| GET | `/` | everyone | list published posts |
| GET | `/posts/:id` | everyone | read a post + its comments |
| POST | `/posts/:post_id/comments` | everyone | leave a comment |
| GET/POST/… | `/admin/posts…` | signed-in author | manage posts |
| GET/POST | `/users/sign_in`, `/users/sign_up` | author | auth (generated by `--auth`) |

## Create the app

Scaffold a new application with authentication baked in, then set up the database:

```bash
# --auth adds doido-auth and runs auth:install (User model, sign-in/up controllers + routes)
doido new blog --database=sqlite --auth
cd blog

cargo doido db create
cargo doido db migrate      # creates the users table

cargo doido server          # http://0.0.0.0:3000 — sign-in/up already work
```

`--auth` gives you a `User` model, a `SessionsController` and `RegistrationsController`, and
sign-in / sign-up / sign-out routes under `/users`. We'll lean on those to protect the admin
area. See the [Auth reference](@/docs/reference/auth.md) for the full picture.

## The Post model

A post has a title, a body, a published flag, and an author (the signed-in `User`). Generate
the model and its migration:

```bash
cargo doido generate model Post \
  title:string:not_null \
  body:text:not_null \
  published:boolean:not_null \
  user:references
cargo doido db migrate
```

`user:references` adds a `user_id` foreign-key column (a non-null `i64`). The generator writes
`app/models/post.rs` — a plain [sea-orm](@/docs/reference/models.md) entity. Add the
relations so we can navigate from a post to its comments and its author:

```rust
// app/models/post.rs
use doido::model::sea_orm::entity::prelude::*;

#[derive(Clone, Debug, PartialEq, DeriveEntityModel)]
#[sea_orm(table_name = "posts")]
pub struct Model {
    #[sea_orm(primary_key)]
    pub id: i64,
    pub title: String,
    pub body: String,
    pub published: bool,
    pub user_id: i64,
}

#[derive(Copy, Clone, Debug, EnumIter, DeriveRelation)]
pub enum Relation {
    #[sea_orm(has_many = "super::comment::Entity")]
    Comments,
    #[sea_orm(
        belongs_to = "super::user::Entity",
        from = "Column::UserId",
        to = "super::user::Column::Id"
    )]
    User,
}

impl ActiveModelBehavior for ActiveModel {}
```

While we're here, add a tiny validation so blank posts are rejected. Doido's
[`Validate`](@/docs/reference/models.md) trait collects errors into an accumulator:

```rust
use doido::model::validation::{Validate, Errors};

impl Validate for Model {
    fn validate(&self) -> Errors {
        let mut e = Errors::new();
        e.presence("title", &self.title);
        e.length("body", &self.body, Some(10), None); // at least 10 characters
        e
    }
}
```

The generator also dropped a `tests/post_model_test.rs` stub — we'll fill it in under
[Testing](#testing).

## The Comment model

A comment belongs to a post and carries the reader's name and message. No login is required to
comment, so we just store a free-text name:

```bash
cargo doido generate model Comment \
  post:references \
  author_name:string:not_null \
  body:text:not_null
cargo doido db migrate
```

Add the inverse relation back to `Post`:

```rust
// app/models/comment.rs
#[derive(Copy, Clone, Debug, EnumIter, DeriveRelation)]
pub enum Relation {
    #[sea_orm(
        belongs_to = "super::post::Entity",
        from = "Column::PostId",
        to = "super::post::Column::Id"
    )]
    Post,
}
```

## Routing

Open `config/routes.rs` and describe the app. Keep the auth routes that `--auth` already
injected; add the public routes, the comment route, and the admin namespace:

```rust
// config/routes.rs
use crate::controllers::{CommentsController, PostsController};
use crate::controllers::admin::PostsController as AdminPostsController;
use doido::controller::{axum, routes};

pub fn router() -> axum::Router {
    routes! {
        root!(PostsController::index);                       // GET /
        resources!(posts, PostsController, only: [index, show]);
        post!("/posts/:post_id/comments", CommentsController::create);

        namespace!(admin, {                                  // path + helper prefix "admin"
            resources!(posts, AdminPostsController);         // /admin/posts … (all 7 routes)
        });

        // The /users sign-in, sign-up and sign-out routes were injected by --auth — leave them.
    }
}
```

`namespace!(admin, …)` prefixes both the URL (`/admin/posts`) and the generated path helpers
(`admin_posts_path()`), so they never collide with the public `posts_path()`. See
[Controllers & routing](@/docs/reference/controllers.md) for the full DSL.

## The public blog

The public controller reads from the database via `ctx.db()` and renders Tera templates. Create
`app/controllers/posts_controller.rs`:

```rust
// app/controllers/posts_controller.rs
use crate::models::{comment, post};
use doido::controller::{controller, Context, Response};
use doido::model::serialization::as_json;
use doido::model::{ColumnTrait, EntityTrait, QueryFilter};
use serde_json::json;

pub struct PostsController;

#[controller]
impl PostsController {
    pub async fn index(ctx: Context) -> Response {
        let posts = post::Entity::find()
            .filter(post::Column::Published.eq(true))
            .all(ctx.db())
            .await
            .unwrap_or_default();

        ctx.render("posts/index", json!({ "posts": as_json(&posts) }))
    }

    pub async fn show(ctx: Context) -> Response {
        let Some(id) = ctx.param("id").and_then(|s| s.parse::<i64>().ok()) else {
            return ctx.status(404);
        };

        let Ok(Some(post)) = post::Entity::find_by_id(id).one(ctx.db()).await else {
            return ctx.status(404);
        };

        let comments = comment::Entity::find()
            .filter(comment::Column::PostId.eq(post.id))
            .all(ctx.db())
            .await
            .unwrap_or_default();

        ctx.render(
            "posts/show",
            json!({ "post": as_json(&post), "comments": as_json(&comments) }),
        )
    }
}
```

Register it in `app/controllers/mod.rs` (the generator maintains this list; add the modules if
they aren't there yet):

```rust
// app/controllers/mod.rs
pub mod admin;
pub mod comments_controller;
pub mod posts_controller;

pub use comments_controller::CommentsController;
pub use posts_controller::PostsController;
```

### Views

Templates live under `app/views/<controller>/<action>.html.tera` and are rendered as
**fragments** wrapped by `app/views/layouts/application.html.tera`, which yields with
`{{ content_for_layout }}` — there's no `{% extends %}`. The JSON you pass to `ctx.render`
becomes the template context.

```html
{# app/views/posts/index.html.tera #}
<h1>Blog</h1>
{% for post in posts %}
  <article>
    <h2><a href="/posts/{{ post.id }}">{{ post.title }}</a></h2>
  </article>
{% endfor %}
```

```html
{# app/views/posts/show.html.tera #}
<article>
  <h1>{{ post.title }}</h1>
  <p>{{ post.body }}</p>
</article>

<section>
  <h2>Comments</h2>
  {% for comment in comments %}
    <p><strong>{{ comment.author_name }}</strong>: {{ comment.body }}</p>
  {% endfor %}

  <form method="post" action="/posts/{{ post.id }}/comments">
    <input type="text" name="author_name" placeholder="Your name" required>
    <textarea name="body" placeholder="Your comment" required></textarea>
    <button type="submit">Post comment</button>
  </form>
</section>
```

## Comments

The comment form above posts to `CommentsController::create`. It reads the form body into a
typed struct, inserts a row, and redirects back to the post. Create
`app/controllers/comments_controller.rs`:

```rust
// app/controllers/comments_controller.rs
use crate::models::comment;
use doido::controller::{controller, Context, Response};
use doido::model::{ActiveModelTrait, Set};
use serde::Deserialize;

#[derive(Deserialize)]
struct NewComment {
    author_name: String,
    body: String,
}

pub struct CommentsController;

#[controller]
impl CommentsController {
    pub async fn create(ctx: Context) -> Response {
        let Some(post_id) = ctx.param("post_id").and_then(|s| s.parse::<i64>().ok()) else {
            return ctx.status(404);
        };

        let Ok(form) = ctx.form::<NewComment>().await else {
            return ctx.redirect_to(format!("/posts/{post_id}"));
        };

        let comment = comment::ActiveModel {
            post_id: Set(post_id),
            author_name: Set(form.author_name),
            body: Set(form.body),
            ..Default::default()
        };
        let _ = comment.insert(ctx.db()).await;

        ctx.redirect_to(format!("/posts/{post_id}"))
    }
}
```

## The author admin area

The admin area is an ordinary controller placed in an `admin` module and guarded by a
`before_action` filter. When the author signs in, `doido-auth` stores their id in the
session; the filter reads it back and, if nobody is signed in, halts the request and
redirects to the sign-in page. (You could instead take the `CurrentUser<User>` extractor as
an action argument, as the generated `auth:scaffold` does — see the
[Auth reference](@/docs/reference/auth.md); here we keep it explicit.)

Create `app/controllers/admin/mod.rs`:

```rust
// app/controllers/admin/mod.rs
pub mod posts_controller;
pub use posts_controller::PostsController;
```

Then `app/controllers/admin/posts_controller.rs`:

```rust
// app/controllers/admin/posts_controller.rs
use crate::models::post;
use doido::controller::{controller, Context, Response};
use doido::model::serialization::as_json;
use doido::model::{ActiveModelTrait, ColumnTrait, EntityTrait, QueryFilter, Set};
use serde::Deserialize;
use serde_json::json;

// Halts and redirects to sign-in unless someone is signed in. Sign-in stores the
// user's id in the session under "user_id" (see doido-auth).
async fn require_login(ctx: &mut Context) -> Result<(), Response> {
    if ctx.session().get::<i64>("user_id").is_none() {
        return Err(ctx.redirect_to("/users/sign_in"));
    }
    Ok(())
}

#[derive(Deserialize)]
struct PostForm {
    title: String,
    body: String,
    published: Option<String>, // an unchecked checkbox is simply absent
}

pub struct PostsController;

#[controller]
impl PostsController {
    #[before_action(require_login)]
    pub async fn index(mut ctx: Context) -> Response {
        let author_id = ctx.session().get::<i64>("user_id").unwrap();
        let posts = post::Entity::find()
            .filter(post::Column::UserId.eq(author_id))
            .all(ctx.db())
            .await
            .unwrap_or_default();

        ctx.render("admin/posts/index", json!({ "posts": as_json(&posts) }))
    }

    #[before_action(require_login)]
    pub async fn new(ctx: Context) -> Response {
        ctx.render("admin/posts/new", json!({}))
    }

    #[before_action(require_login)]
    pub async fn create(mut ctx: Context) -> Response {
        let author_id = ctx.session().get::<i64>("user_id").unwrap();
        let Ok(form) = ctx.form::<PostForm>().await else {
            return ctx.redirect_to("/admin/posts/new");
        };

        let post = post::ActiveModel {
            title: Set(form.title),
            body: Set(form.body),
            published: Set(form.published.is_some()),
            user_id: Set(author_id),
            ..Default::default()
        };
        let _ = post.insert(ctx.db()).await;

        ctx.redirect_to("/admin/posts")
    }

    // edit / update / destroy follow the same shape: read author_id from the session,
    // load the post, check it belongs to that author, then render, save, or delete.
}
```

Register the module in `app/controllers/mod.rs` (we already added `pub mod admin;` above).

Two minimal admin templates:

```html
{# app/views/admin/posts/index.html.tera #}
<h1>Your posts</h1>
<a href="/admin/posts/new">Write a post</a>
<ul>
  {% for post in posts %}
    <li>
      {{ post.title }}
      {% if post.published %}(published){% else %}(draft){% endif %}
    </li>
  {% endfor %}
</ul>
```

```html
{# app/views/admin/posts/new.html.tera #}
<h1>New post</h1>
<form method="post" action="/admin/posts">
  <input type="text" name="title" placeholder="Title" required>
  <textarea name="body" placeholder="Write your post…" required></textarea>
  <label><input type="checkbox" name="published" value="1"> Publish now</label>
  <button type="submit">Save</button>
</form>
```

## Run it

```bash
cargo doido server
```

Now walk the whole flow:

1. Visit `/users/sign_up` and register the author account.
2. Go to `/admin/posts`, write a post, and tick **Publish now**.
3. Open `/` — the published post appears. Click through to `/posts/:id`.
4. Leave a comment; it shows up under the post.

Signing out (`DELETE /users/sign_out`) and revisiting `/admin/posts` bounces you back to the
sign-in page — that's `require_login` doing its job.

## Testing

Doido apps are tested with plain `#[tokio::test]` functions. Three kinds of tests cover this
blog: a **model** test, a **request** test, and an **auth** test. Run them all with `cargo
test` (or a single one with `cargo test <name>`).

### Model tests

`TestDb` spins up an isolated in-memory SQLite database. Create the table, insert a row, and
assert it round-trips. This is the stub the generator left in `tests/post_model_test.rs`:

```rust
// tests/post_model_test.rs
#[path = "../app/models/mod.rs"]
mod models;

use doido::model::sea_orm::{ConnectionTrait, Schema};
use doido::model::{ActiveModelTrait, EntityTrait, Set, TestDb};
use models::post;

#[tokio::test]
async fn creates_and_finds_a_post() {
    let db = TestDb::new().await.unwrap();

    // Build the posts table from the entity definition.
    let backend = db.conn().get_database_backend();
    let stmt = Schema::new(backend).create_table_from_entity(post::Entity);
    db.conn().execute(backend.build(&stmt)).await.unwrap();

    let created = post::ActiveModel {
        title: Set("Hello".into()),
        body: Set("My first post, long enough.".into()),
        published: Set(true),
        user_id: Set(1),
        ..Default::default()
    }
    .insert(db.conn())
    .await
    .unwrap();

    let found = post::Entity::find_by_id(created.id)
        .one(db.conn())
        .await
        .unwrap()
        .unwrap();

    assert_eq!(found.title, "Hello");
    assert!(found.published);
}
```

Validations are pure logic, so they need no database at all:

```rust
#[test]
fn rejects_a_blank_post() {
    use doido::model::validation::Validate;

    let post = models::post::Model {
        id: 0,
        title: String::new(),      // missing
        body: "too short".into(),  // < 10 chars
        published: false,
        user_id: 1,
    };

    assert!(!post.is_valid());
    // post.validate().full_messages() lists the human-readable errors.
}
```

### Request tests

Request tests mount the real router and drive it with an in-process client — no live server.
This mirrors the request test Doido's own `scaffold` generator produces: include the app modules
with `#[path]`, install an in-memory pool once in `setup()`, then assert on status codes.

```rust
// tests/posts_request_test.rs
#[path = "../app/controllers/mod.rs"]
mod controllers;
#[path = "../app/models/mod.rs"]
mod models;
#[path = "../config/routes.rs"]
mod routes;

use doido::controller::axum;
use doido::model::sea_orm::{ConnectionTrait, Database, Schema};
use models::post;
use tower::ServiceExt; // for `oneshot`

async fn setup() {
    if doido::model::pool::try_pool().is_none() {
        let db = Database::connect("sqlite::memory:").await.unwrap();
        let _ = doido::model::pool::set_pool(db);
    }
    let db = doido::model::pool::pool();
    let backend = db.get_database_backend();
    let stmt = Schema::new(backend).create_table_from_entity(post::Entity);
    let _ = db.execute(backend.build(stmt.if_not_exists())).await;
}

#[tokio::test]
async fn index_is_public() {
    setup().await;

    let response = routes::router()
        .oneshot(
            axum::http::Request::get("/")
                .body(axum::body::Body::empty())
                .unwrap(),
        )
        .await
        .unwrap();

    assert_eq!(response.status(), axum::http::StatusCode::OK);
}

#[tokio::test]
async fn admin_redirects_when_signed_out() {
    setup().await;

    let response = routes::router()
        .oneshot(
            axum::http::Request::get("/admin/posts")
                .body(axum::body::Body::empty())
                .unwrap(),
        )
        .await
        .unwrap();

    // require_login halts and redirects to the sign-in page.
    assert_eq!(response.status(), axum::http::StatusCode::FOUND);
}
```

For simple cases, `doido_controller::testing::send(router, "GET", "/", "")` returns the status
and body in one call instead of building the request by hand.

### Auth tests

To exercise a *signed-in* request, `doido-auth` ships an in-memory testing harness. `seed_user`
creates a user, and `sign_in_request` returns a request already carrying the session:

```rust
// tests/admin_auth_test.rs
use doido_auth::testing::{seed_user, sign_in_request, AuthTestGuard};

#[tokio::test]
async fn author_can_reach_the_admin_area() {
    let _guard = AuthTestGuard::new();
    // …set up the pool + tables as in the request test…

    seed_user(pool, "author@example.com", "s3cret").await.unwrap();
    let response = sign_in_request(&app, "author@example.com", "s3cret").await.unwrap();

    assert_eq!(response.status(), axum::http::StatusCode::OK);
}
```

See the [Auth reference](@/docs/reference/auth.md#testing) for the full list of helpers.
