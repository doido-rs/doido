# doido-router — Spec

Rails analogue: **Action Dispatch / Router**

> **Status (2026-11-13):** The `routes!` macro lives in **`doido-controller`**. Implemented:
> `resource!` (7 REST plural by default, `singular: true` for profile-style resources,
> nested blocks, `only`/`except`), `namespace!`/`scope!`, `member`/`collection` on verb
> macros inside a resource block, `redirect!`, `mount!`, and compile-time URL helpers.
> **Open:** route constraints beyond path params (format/subdomain/custom).

## Decisions (resolved in interview)

- **Route definition style:** Macro DSL — primary and only API
- **`resource!` generates all 7 REST routes by default** (plural), with `only:` / `except:` options to restrict
- **`singular: true`** — Rails `resource :profile` (no index, no `:id` on show)
- **Nested resources** — `resource!(posts, PostsController, { resource!(comments, CommentsController); })`
- Named route URL helpers generated by the macro (compile-time)

## Macro DSL Design

```rust
routes! {
    resource!(posts, PostsController);
    resource!(comments, CommentsController, only: [index, show]);
    resource!(admin, AdminController, except: [destroy]);

    resource!(posts, PostsController, {
        get!(collection: "search", PostsController::search);
        get!(member: "preview", PostsController::preview);
        resource!(comments, CommentsController);
    });

    resource!(profile, ProfileController, singular: true);

    get!("/about", PagesController::about);
    post!("/login", SessionsController::create);

    namespace!(api, {
        resource!(users, Api::UsersController);
    });

    scope!("/v2", {
        resource!(articles, V2::ArticlesController);
    });
}
```

## 7 REST Routes generated by `resource!(name, Controller)` (plural, default)

| Helper          | Method | Path                  | Action    |
|-----------------|--------|-----------------------|-----------|
| `posts_path()`  | GET    | /posts                | index     |
| `new_post_path()` | GET  | /posts/new            | new       |
| `post_path(id)` | GET    | /posts/:id            | show      |
| `post_path(id)` | POST   | /posts                | create    |
| `edit_post_path(id)` | GET | /posts/:id/edit    | edit      |
| `post_path(id)` | PATCH  | /posts/:id            | update    |
| `post_path(id)` | DELETE | /posts/:id            | destroy   |

## API-only projects (`doido new --api`)

A project generated with `--api` carries `api_only = true` under `[app]` in
`config/application.toml`. The route macros read this marker **at compile time**
(via `CARGO_MANIFEST_DIR`) and, in API mode, plural `resource!` (and nested
resources) omit the HTML-form routes — `new` and `edit` — along with their
helpers. JSON-relevant actions are kept, **including `destroy` (DELETE)**.
`only:` / `except:` still apply on top.

## Known Requirements

- Built on top of `axum::Router` internally
- Routes map to controller actions (not raw closures)
- Must support: GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS
- Route parameters extracted and typed via serde
- URL helpers generated by the `routes!` macro at compile time
- `namespace!` prefixes both path and module path
- `scope!` prefixes only the path
